# 批量查询规划与Q&A用法

数据源为`wind_terminal_api`。用户于2026-10-03提供32项Wind API Q&A，其中批量分组、报告期日历、空值和超限说明可与本机已保存的官方接口FAQ交叉阅读。旧Windows/COM安装和R/MATLAB示例需要按当前Mac WindPy环境判断，不照搬执行。

## 先规划，再按需求执行

使用`plan_wind_data_queries(method="wsd"或"wss", arguments=<原生参数>, limit=20, offset=0)`。规划完全在本地完成，不调用Wind、不消耗API取数额度、不识别证券名称，也不证明字段或权限有效。代码、字段及必要选项仍需由正式文档、代码生成器或已核验示例确认。

WSD是代码×字段×日期数据中的二维切片：一次可取一个代码的多个字段，或多个代码的一个字段。规划器比较按代码循环、按字段循环及两种尾部分组，在本MCP每次50代码、100字段限制内选择请求数较少的方案。未证明任意分组下的全局最优。WSS按代码和字段分块；不会将WSD自动改写成按日期循环的WSS，因为两种接口的日期选项与字段适用性需分别确认。

例如90个实际期货代码、3个字段、同一日期范围，WSD按字段分为6次请求，优于按90个代码逐个请求。这减少往返次数；**代码×字段×日期的数据量并未减少，不能用来绕过Wind提取限额**。

1. 请求规划，读取`total_requests`、`selected_strategy`、`quota_observation`及`requests`。规划器上限为10000代码、500字段；不会静默截断，过大时明确报错。
2. 若`next_offset`非空，以相同method和arguments继续分页。每页`plan_id`应相同；更改代码顺序、字段、日期或options后是另一个计划。分页只分页计划，不取数据。
3. 当前允许取数时，将每条的`method`和`arguments`传给`query_wind_data`。遇到超限或其他失败先停止并保存完成项及错误，不继续展开。当前账户额度未知时，不把成功生成计划理解为额度已恢复。
4. 保留每条原始回执。`code_slice`、`field_slice`是原输入中从0开始、结束位置不包含的区间；组装结果仍须核对原始Codes、Fields和Times，不按二维数组位置盲拼。

规划器不切分时间区间，原来的options字符串保持不变。Q&A指出前填不会自动追溯查询起点之前的数据，因此拆日期后分别前填可能改变结果，不能将日期分块当作无影响的通用优化。

需要复用已保存数据时直接使用`read_wind_receipt`或本地分析工具。`query_wind_data(max_age_seconds>0)`是原生请求完全匹配、在明确容忍时间内的缓存选项；默认0仍会取新数据。缓存不是实时行情，也不证明历史当时可得。

## 财报日历、参数与缺失

- Q&A第8/31项：报告期与公告日期、交易日不同，报告期可能落在非交易日。WSD财报序列通常应核对`Period=Q;Days=Alldays`。本机已有`oper_rev`季度日历对照回执；不能把这组参数自动套到行情或全部财务指标。
- 第9/10项：检查代码、字段、半角分隔符和`Key=Value;Key=Value`选项；必要的`rptType`等要由指标说明确认，不全局补`rptType=1`。规划器可拦截代码/字段中的全角分隔符及重复项，但不是完整选项字典。
- 第11项：NaN与0必须区分；说明中提到WSQ在无数据时可能返回0，故0不能单凭接口成功判为真实市场观测。MCP保留Wind原值，将非有限数序列化为null。默认不注入`Fill=Previous`或`showblank=0`；用户明确给出的参数原样保留并在分析时说明其影响。
- 第19项：指数权重可能滞后于成分。此前沪深3009月29日请求返回9月1日行日期，MCP保留两个日期；该样本不能扩展成所有指数固定滞后一个月。
- 第24项：入库时间说明是一般经验，不作为全市场完成入库的保证。查看真实返回日期、空值和字段，而非按本地时钟补值。

## 超限与运行边界

第23/29项确认`quota exceed`与近期提取量、账户限额有关，未提供本账户余额或恢复时刻。已保存的Client API帮助另述过去7×24小时滚动用量；不能推定次日零点重置。国庆期间用户无法查看额度或联系客户经理，保持待确认状态，停止批量取数；本地计划、参数检索、回执分析和客户端配置仍可使用。

本地`quota_observation`是当前配置下近期错误记录，既不是余额查询，也不是永远不可用的断言。读取官方文档不构成当前SDK行为认证，减少请求次数也不会授予额外数据权限。详细审阅记录为`references/user-faq-review-20261003.json`。
