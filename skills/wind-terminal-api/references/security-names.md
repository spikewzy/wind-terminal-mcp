# 证券名称与市场歧义

Alice 的股票、场内基金和指数行情工具接受证券名称。WindPy 适配器在对应的 `*_price_indicators`、`*_kline`、`*_quote` 共9个入口中，增加了通过官方 `w.wai("fer", text)` 解析名称的流程。

## 调用与选择规则

- 明确的带后缀代码直接进入原来的查询，不额外识别名称。它是调用者指定的代码，不代表适配器另行认证了资产类别。
- 快照允许最多50个名称或代码，以英文逗号分隔，返回顺序与输入一致；K线和分钟行情每次一个证券。
- 对需要识别的名称一次按行提交 WAI。返回段数必须一致，实体文本和起止位置必须覆盖整个名称；不把基金名称中的指数片段当成基金本身。
- 股票只接受 `stockCN/stockHK/stockUS`，基金接受 `fund`，指数接受 `indicator`；还必须返回完整证券代码。财务实体的数字 ID、EDB ID、企业 ID 都不能当作证券代码。
- 检查主结果和全部备选项，按代码去重后只有一个才使用。置信度高低不改变这一规则；ADR、港股和A股不自动合并。场外 `.OF` 基金候选不用于场内价格接口。
- 任一输入有歧义或未识别，返回 `SECURITY_SELECTION_REQUIRED`，整个批次不进行行情查询。不同输入指向同一代码时也不悄悄去重，而是返回 `DUPLICATE_SECURITY_SELECTION`。

例如可调用 `call_alice_tool_on_windpy`：

```json
{
  "server_type": "stock_data",
  "tool_name": "get_stock_kline",
  "params": {
    "windcode": "贵州茅台",
    "begin_date": "2026-09-28",
    "end_date": "2026-09-29",
    "count": -1
  }
}
```

实测中，`中国平安` 同时出现 `601318.SH`、`2318.HK`、`PNGAY.OO`；`腾讯控股` 出现 `0700.HK`、`TCTZF.OO`。已有任务上下文足以确定市场时，用明确代码继续；否则澄清市场，不按候选顺序选择。其他名称仍以每次真实识别结果为准，不使用固定名称表替代查询。

## 证据和返回值

结果中的 `security_resolution` 保留原输入、候选、选择规则、WAI 原始 `receipt_id` 与指纹，以及独立的 `derived_receipt_id`。后者可用 `read_wind_receipt` 读取完整名称选择记录。它与行情的原始回执、K线截取后的回执是不同记录；截取后的结果也保留名称证据。

行情查询失败时，错误中保留已成功的名称选择证据。识别成功不代表行情权限可用，更不能把 Wind 终端错误转成 Alice MCP 错误。所有查询和派生记录仍为 `wind_terminal_api`。

证据：

- `verification/security-name-probe.json`：八行真实 WAI 输入，核对股票、基金、指数、裸数字代码及财务指标的类型和段落关系。
- `verification/mcp-security-names.json`：股票日K、ETF分钟、指数与混合输入快照、同名多市场拒绝、明确代码继续查询，以及回执读取。
- 类型说明来自官方文档 `references/official-help/ai.md` 的“返回实体类型说明”。

ETF样本还保留了2026-09-29 14:59的空价格和零成交量，15:00有有效数据。名称识别成功不意味着每个分钟都有价格；不填零、不前填、不删除缺失记录。本功能不改变已有的复权、停牌、单位、历史日期或数据缺失政策，也没有替代其他领域的自然语言字段选择。
